\begin{abstract}
LLM pipelines increasingly translate clinical guideline text into executable
logic, and are evaluated on \emph{coverage}, which cannot distinguish a rule faithful to its source
from one that is not, and rises when a system fills a gap it cannot resolve with a default. We present \textsc{GuidelineForge}, a tool with a pipeline that converts an
open-access guideline document into CQL and a three-valued checker, in which
every emitted rule cites the exact source sentence it was derived from.
\textsc{GuidelineForge} treats refusal as a measured output, reporting six
distinct reasons a statement could not be encoded alongside the rules that were
produced. It keeps an undefined predicate as a free variable rather than
substituting a default: across the $4{,}304$ rule-record pairs where such a
substitution applies, filling the gap with \texttt{false} falsely certified
$207$ of them as compliant. It treats deontic force as an operator in the
language rather than a label attached afterwards, so a permission has no
violating patient by construction. A user can upload a guideline, inspect any
rule beside the sentence it came from, and check a patient record against it.
\end{abstract}

\section{Introduction}
\label{sec:intro}
\budget{1.5 pp}

Clinical practice guidelines specify, in natural language, the conditions under which a given action should or should not be taken. A growing body of work translates guideline text into a machine-checkable representation that can be run against structured patient data. PathWISE uses a five-stage LLM pipeline separating knowledge extraction from executable clinical logic \citep{pathwise}; Xie and Du use a SAT solver to detect logical inconsistencies between recommendations that standalone LLMs miss \citep{xiedu}; MedGuideX compiles guidelines into executable decision functions and uses them as a training oracle \citep{medguidex}; Leonardi et al. derive rules from guideline text and score conformance across an event log of patient traces \citep{leonardi}.

Systems of this kind are almost universally evaluated, and in practice optimised, for \emph{coverage}: the fraction of guideline statements successfully translated into a rule. Coverage is cheap to compute and rises monotonically as a system is made more permissive, but it does not distinguish a rule faithful to its source from one that is not. This motivates our solution: a system that reports it could not encode a statement makes a true claim about its own limits; one that silently fills the gap makes a false claim about the patient. We therefore treat refusal as a measured output rather than a failure to minimise, and present a system built on that principle.

Three approaches to the underlying problem each fail to prevent this class of error, for specific and demonstrable reasons. The first is \textbf{substituting a default}. Faced with a guideline stating that a drug should be started ``if eGFR is below 30 or the patient is at high risk'' without defining high risk, other solutions often substitute \texttt{false} for nodes its audit marks uncomputable, preserving compilability while surfacing the node for human review \citep{pathwise}. Substituting \texttt{false} in a conjunctive position removes the branch, so a patient qualifying only via that criterion is never routed down it. Section~\ref{sec:necessity} quantifies how often such a default changes a verdict.

The second is \textbf{detecting vagueness by sampling for disagreement} \citep{ksample}: an ambiguous statement admits multiple readings, so repeated formalisation attempts should disagree, yielding a signal that needs no labelled data. This assumes a model facing ambiguity guesses differently each time rather than settling on one answer --- or one refusal. Given ``eGFR below 45 and the patient is frail,'' our runs recognised the same gap on every attempt and declined consistently, leaving no disagreement to detect even though the statement is underspecified. Our gate instead makes refusal an explicit branch of a single constrained decode, so the signal comes from one call.

The third is \textbf{asking a model directly whether a statement is too vague to formalise}. This is circular — the model that struggles with vague language adjudicates its own vagueness — and empirically weak even when purpose-built, reaching around 0.71 F1 \citep{errorcat}.

\section{Method}
\label{sec:design}
\budget{1.25 pp}
\subsection{Pipeline architecture}

Details of the 4 stages of the pipeline: extraction, grounding, formalization, and checking are outlined below (Figure~\ref{fig:arch}). Extraction takes a guideline document and produces a \emph{statement}: text that is verbatim and locatable, carrying a locator and character offsets that let it be re-found in the source. Grounding produces a \emph{registry}: a closed vocabulary in which every name has been resolved to a version-pinned clinical code, or, when it could not be resolved, is declared absent. Formalization takes a statement and a registry and produces a \emph{rule} $\Phi_R = \mathit{when} \rightarrow \mathit{then}$ under a deontic operator, decoded against a grammar whose variable and event names are the registry's to ensure an unknown name is a symbol the grammar does not contain. Checking takes a rule and a partial patient record and produces: 1) one of the three-valued verdicts of Proposition ~\ref{prop:exhaustive} (\textsc{must-violate}, \textsc{certified-compliant}, and \textsc{may-violate}), and 2) a minimized witness when the verdict is undetermined (\S\ref{sec:may}). Interpretation is the only with no deterministic algorithm, but research has shown LLMs are sufficiently capable at this task \citep{dsp}. Concrete technology -- terminology APIs, the LLM, and a separate CQL runtime, storage, etc. -- are outlined in Figure~\ref{fig:tech_stack}. 

Only four components call an LLM, and each has an output space too small to contain the pipeline's characteristic failure mode: the mention proposer returns exact substrings, the terminology selector returns an index into a candidate list or abstains --- a hallucinated code is not a value its output type can express --- and the rule decoder's enumerations come from the registry that statement produced, so a concept that failed to bind cannot appear in a rule. Everything else, including the lowering to CQL, is deterministic. Every rule is compiled by HL7's \texttt{cql-to-elm} translator before it ships; one the translator rejects is recorded as rejected rather than counted as encoded, and an absent toolchain is reported as absent, never as a pass.

A statement that cannot be carried through this narrowing becomes a \emph{refusal}, one of the six reason codes of Table~\ref{tab:attribution}. The residue is measured with the same rigour as the rules, which is what a coverage number cannot provide: a refusal reason is itself informative about the guideline -- a vague qualifier, a permissive recommendation, an obligation the source states is overridable -- rather than merely an admission of the tool's limits. Two of the six are set deterministically; the other four are gated by deterministic checks even where the final call is the model's.

\subsection{Justification for design choices}
\label{sec:necessity}
\subsubsection{Procedure}
We perform an ablation with every guard in the checker, and measure the difference in verdicts about a patient. For a rule $R$ and a partial patient record $P$ we compute the verdict of the
full system and of the system with exactly one guard disabled, and record
whether and how the verdict moved. Records are drawn from the
solver, so every value satisfies the domain theory; each record pins a random
subset of the rule's variables and leaves the rest free, since a fully
determined record admits no \textsc{may-violate} and would make the comparison
vacuous. Half of each rule's records are drawn from $\mathcal{D} \wedge \neg
\Phi_R$ -- completions in which the rule really is broken -- because
uniformly sampled records almost never reach the region where two encodings
disagree. Runs are deterministic given a seed; see Appendix~\ref{app:repro}. Verdicts are \textsc{must-violate}, \textsc{certified-compliant} and \textsc{may-violate} for an obligation, and \textsc{option-taken},
\textsc{option-not-taken}, \textsc{option-available} and \textsc{option-not-applicable} for a permission. A move is counted when the ablated verdict is \textsc{certified-compliant} and the full verdict is not (a patient cleared where the source was silent), or when it is \textsc{must-violate} and the full verdict is not (a false alert). For a permission, any violation verdict counts as the second case including \textsc{may-violate}, since the permission lattice has no accusing state. Transitions within a lattice, and losses of certainty in the safe direction, are recorded but not counted.

The rules are generated. Measured over the rules the system happens to have produced, each row would rest on between $2$ and $6$ rules -- not a sample but an accident of which guidelines are open access. We therefore enumerate the space the language can express: undefined predicate in the antecedent, in the consequent, or absent; obligation or permission; numeric threshold, boolean, time window, or relative change; one atom, two under conjunction, or two under disjunction. Two instances per cell over $72$ cells gives $144$ rules. Every generated rule is put through the same \texttt{validate\_rule} function and non-degeneracy check the pipeline applies to a rule a model wrote, and no candidate was rejected -- so each is a rule the system would have accepted.

one is unsafe in both directions, by position:

obligations, substituting \textsf{false} clears $9.6\%$ of pairs and accuses

measured is dropping the deontic operator: once a rule is permissive, this
changes the verdict for four pairs in five, always into an alert on a patient

physiological range; the pipeline currently supplies none, so a rule it
produces is checked against a weaker domain theory. Re-running the sweep with
the ranges stripped moves every rate by less than half a point

\subsubsection{Justification for undetermined verdicts}
\label{sec:may}

A verdict of \textsc{may-violate} is only useful if the reader is told what it
turns on. \texttt{minimal\_counterexample\_core} returns the smallest set of those values that on its own forces the violation, by deletion-based extraction: drop one assignment, keep the drop if the remainder still cannot be made compliant. Because the check leaves every non-core variable unconstrained, unsatisfiability quantifies over all their completions, so the core's values force a violation \emph{whatever the unmeasured variables turn out to be}.

Of $5{,}764$ records, $1{,}783$ returned \textsc{may-violate}. The core is smaller than the set of unstated variables ($1.39$ against $2.42$ on average), and the reduction grows as the record thins (Table~\ref{tab:coresize}, Appendix~\ref{app:extra}), because the core is bounded by the rule's structure -- the number of atoms that must be forced -- and not by how much the record omits.


$1{,}165$ of the $1{,}783$ undetermined verdicts ($65.3\%$) rest on a single
variable, but $126$ of those name an \emph{undefined predicate} --- a phrase the
source states and never defines --- which no measurement resolves. A system
substituting a value for those would return a definite verdict every time,
asserting something the source does not say. The distinction is visible here:
the system can say which undetermined verdicts wait on a measurement and which
wait on a definition the guideline never gave.

\emph{Single-variable core} is the share of verdicts in that row
  whose core names one variable. A single-variable core is not the same as a resolvable measurement: the core establishes that one assignment forces a violation, whereas measuring the variable helps only if \emph{every} value of it determines the verdict (Proposition~\ref{prop:settle}). Of the $1{,}183$ single-variable cores this experiment sees, measuring the named
variable determines the verdict in $840$ ($71.0\%$), which is $46.6\%$ of all
undetermined verdicts. In the other $343$ ($29.0\%$) some value of it leaves the
case open, and $147$ of those name an undefined predicate, where no measurement
exists to take. The naive reading --- counting single-variable cores as
resolvable measurements --- would have claimed $65.7\%$ and overstated by nearly
a third (Appendix~\ref{app:repro}). 

\subsection{Language design}

Every concept the language can talk about must be declared and bound to a real code before it can be referenced, so a term means exactly one thing. Conditions are built from a deliberately small grammar: four leaf comparisons (scalar comparison, range, time-since-event, change-from-baseline) and three connectives (negation, conjunction, disjunction), which keeps every rule inside a fragment a solver can decide. Figure~\ref{fig:language_shorten} (Appendix~\ref{app:extra}) carries one worked example through all three layers.

A rule is a formula wrapped in an obligation or permission and never carries a labelled action; the recommended action, its target, and the source sentence are metadata for a human reviewer, not something evaluation logic branches on. The three-valued verdict sits naturally in the target language: CQL's Boolean type is nullable, so a comparison over an element the record does not contain evaluates to \texttt{null} rather than \texttt{false}, and \texttt{null} propagates through the connectives under Kleene semantics, so the unknown reaches the top-level \texttt{define} instead of collapsing at the leaf.

\section{Limitations, and what a reviewer can run}
\label{sec:limits}
\budget{0.25 pp --- flat, no hedging}
The corpus is nine open-access guidelines, and the sampling frame is not incidental: the documents we could obtain skew towards journals that publish structured, GRADE-style \citep{grade} recommendation abstracts, which are easier to segment than a guideline leaving its recommendations in narrative prose. More generally, guidelines follow no common structure \citep{peleg}, which makes a representative sample difficult to assemble for any system of this kind, and we would expect the residue to grow on documents whose recommendations are narrative rather than structured.

There is no reference corpus with ground truth for this task, and that is a property of the field's existing artefacts. AHRQ's CDS Connect \citep{cdsconnect} is close, publishing decision-support artefacts, but not a labelled set of guideline sentences with the rules they should become. An electronic Clinical Quality Measure \citep{cql} is a cohort definition over a population, not a per-patient recommendation with a source sentence. Building that corpus -- paired intended rules and sentences -- is the obvious next step, and the per-statement refusal log this system emits is a candidate starting point for one.

Finally, no clinician has yet adjudicated the system's output. Clinical review of the generated rules, and of the criteria by which a rule is judged faithful to its source, remains future work. The scope here is narrower by design: whether the artefact says what the sentence said, not whether the sentence should be followed.

\paragraph{Detection: does the checker flag what it should?}
The ablation of Section~\ref{sec:necessity} shows that each guard moves
verdicts; it does not show that the verdicts are right. For that a record needs
a label fixed independently of the checker. \texttt{synthesize\_boundary\_tests.py}
supplies one: for every numeric and temporal boundary in the hand-authored
fixture rules it solves against $\Phi_R$ for a record on the compliant side and
against $\neg\Phi_R$ for one on the violating side, so each record's true label
follows from its construction rather than from our reading of the sentence.
\texttt{detection\_benchmark.py} then pins every variable and re-derives the
verdict through the ordinary checker. All $24$ boundary records matched the
label they were built to carry --- $14$ \textsc{certified-compliant} and $10$
\textsc{must-violate}, with no case flagged in the wrong direction and none
left undetermined once fully pinned. This is a small set over eight fixture
rules, not the generated sweep, so it bounds nothing about what the pipeline
emits; what it establishes is that the three-valued classifier agrees with
ground truth wherever ground truth exists.

\paragraph{What a single call reports instead, and what the second one costs.}
A three-valued verdict needs two satisfiability queries where a naive check
makes one. Over $200$ synthetic patients against $25$ bounded-horizon clauses
--- $5{,}000$ rule--patient pairs over generic \texttt{drug\_N}/\texttt{lab\_N}
names rather than the fixtures, each plan pinning $14$ of $30$ candidate
actions --- the naive single call reports a violation for $2{,}010$ pairs
($40.2\%$). The three-valued checker returns \textsc{must-violate} for none of
them: every one is a case in which some completion of the unmeasured facts is
compliant, and the naive check cannot separate that from a violation because
one query cannot distinguish ``every completion violates'' from ``some
completion violates''. These are randomly generated plans, so no certain
violation is expected --- the point is not that the naive check is wrong about
a patient but that it has no vocabulary in which to be undetermined. The
second query costs $2.1\times$ the first (Table~\ref{tab:perf}); the median
check is $25.2$\,ms and the full sweep runs in $137$\,s, so on this workload
not guessing is not what makes a check slow.

\section{Reproducing the measurements}
\label{app:repro}

\paragraph{Commands.}
Every number in Section~\ref{sec:necessity} and Appendix~\ref{app:extra} comes
from one of the five measurement scripts below, all in
\texttt{patient\_checker/tests}; the last two rows produce no number, and are
listed because they are what a reader would want to run next --- one prints the
rule set, the other machine-checks the propositions. None makes a model call;
none needs an API key; each is invoked separately, for the reason given under
\emph{Determinism} below.
\begin{center}
\begin{tabular}{ll}
  \toprule
  Produces & Command \\
  \midrule
  Tables \ref{tab:generated}, \ref{tab:holepos}
    & \texttt{ablation.py -{}-generated -{}-plans 50 -{}-seed 0} \\
  Core sizes, \S\ref{sec:may}
    & \texttt{explanation\_size.py -{}-plans 50 -{}-seed 0} \\
  Both \textsc{may} experiments, \S\ref{sec:may}
    & \texttt{may\_actionability.py -{}-plans 50 -{}-seed 0} \\
  Detection against ground truth, App.~\ref{app:extra}
    & \texttt{detection\_benchmark.py} \\
  Table \ref{tab:perf}, and the naive check's rate
    & \texttt{benchmark.py} \\
  The rule set itself
    & \texttt{generated\_rules.py -{}-list} \\
  \addlinespace
  The propositions stated in \texttt{logic.tex}
    & \texttt{propositions.py} \\
  \bottomrule
\end{tabular}
\end{center}
Each writes a CSV of per-verdict rows beside a short summary, both in the
artefact; the summaries are what the tables quote.
\texttt{detection\_benchmark.py} imports \texttt{synthesize\_boundary\_tests.py}
and re-solves its boundary records rather than reading a stored file, so the
labels it checks against are regenerated on every run and cannot drift from the
rules.

\paragraph{Environment.}
Python 3.14.2, \texttt{z3-solver} 5.1.0, macOS 15.5 (arm64). The commit is
recorded in the artefact. Beyond the standard library these scripts need only
\texttt{z3-solver} and the repository's own modules --- three of them reach the
checker through \texttt{api.py}, which pulls Flask in with it, though no server
is started and no port is opened. The timings in Table~\ref{tab:perf} are from
this machine, single process, with no other load.

\paragraph{Determinism.}
Runs are reproducible byte for byte given the seed: three separate processes
produce identical CSVs. This required one fix worth recording, because it is
the kind of thing that silently invalidates a reported number. A rule's
variable map is built from a Python \emph{set}, whose iteration order varies
between processes under hash randomisation; the record sampler drew from that
order, so the same seed gave different counts run to run (for one row, $103$
against $104$). The sampler now sorts the names. Anyone reproducing a
solver-driven measurement in Python should check this specifically --- the
symptom is a stable seed with unstable output, and it is invisible within a
single process.

A second limit bounds that guarantee. Each script is reproducible \emph{in its
own process}, but calling the record sampler twice inside one process is not:
at seed $0$ the first pass draws $5{,}764$ records and the second $5{,}760$,
which is exactly the gap between the record counts \texttt{explanation\_size.py}
and \texttt{ablation.py} report. The cause is below our code --- Z3 carries global state
that constructing a fresh solver does not reset, so the second pass draws
different models. Two consequences. Each script must be
invoked separately, which is how the commands above are written. And two scripts
at the same seed do not see an identical record set, so figures from
\texttt{ablation.py} and \texttt{may\_actionability.py} are two samples from one
sampler rather than two views of one sample, and are not row-for-row comparable.

\paragraph{Record counts.}
\texttt{-{}-plans} is a \emph{ceiling}, not a quantity. A record pins a subset
of a rule's variables, so a rule with few variables admits few distinct
records: at \texttt{-{}-plans 50} the actual counts range from $5$ to $50$
(mean $40.0$ over $144$ rules, $5{,}760$ pairs), and the distribution is
bimodal --- $100$ rules reach the ceiling while $8$ admit only $5$ records
each. The unit of analysis is therefore the rule--record pair, and rules
contribute unequally: a reported rate is not the fraction of \emph{rules}
affected.

\paragraph{How \emph{applicable} is determined.}
Every rate is over the pairs the guard can act on, and that set is defined in
code (\texttt{ablation.applies}) rather than by a convention in this paper, so
it is reproducible and auditable:
\begin{center}
\begin{tabular}{ll}
  \toprule
  Guard & Applies to a rule when \\
  \midrule
  substitute \textsf{false} / \textsf{true}
    & it has an undefined predicate of \emph{boolean} sort \\
  deontic operator
    & it is a permission \\
  occurrence flag
    & it mentions an occurrence flag, i.e.\ it contains a time window \\
  three-valued verdict
    & always \\
  \bottomrule
\end{tabular}
\end{center}
The boolean restriction matters: an unbound \emph{event} also leaves free
symbols behind, but they are integer and real valued, and substituting a truth
value into a quantity is meaningless. Those rules are excluded from the
substitution rows rather than coerced. Reporting over all pairs instead would
dilute every rate by the rules the guard cannot touch --- on the generated set
that is $1{,}456$ of $5{,}760$ pairs for the substitution rows alone, and
$4{,}047$ for the occurrence-flag row, which applies to only the $1{,}713$
pairs whose rule contains a time window.

\paragraph{Artefacts.}
\texttt{ablation.py} writes one row per (rule, record, guard) with columns
\texttt{source}, \texttt{rule\_id}, \texttt{deontic}, \texttt{holes},
\texttt{pinned}, \texttt{ablation}, \texttt{applies}, \texttt{full},
\texttt{ablated}, \texttt{direction} --- $28{,}800$ rows, one per
(rule, record, guard) over five guards.
\texttt{explanation\_size.py} writes one row per undetermined verdict with the
count of unstated variables, the core size, and the core's variable names.
\texttt{may\_actionability.py} adds, per verdict, the verdict after the core is
supplied and whether measuring a single-variable core determines the outcome.
Every table in Section~\ref{sec:necessity} can be recomputed from these rows
independently of the scripts' own counters, which is how they were checked.

\paragraph{Verdict transitions.}
The two columns of Section~\ref{sec:necessity} record only whether a verdict
became \textsc{certified-compliant} or \textsc{must-violate}. The full
transition matrix is recoverable from the artefact and is worth inspecting:
printing it is what exposed three separate confounds in the harness, in each
case an ablation that was changing more than one thing at once. Two examples
that are recorded but counted in neither column: a move within the permission
lattice (\textsc{option-available} to \textsc{option-not-taken}), and
\textsc{must-violate} degrading to \textsc{may-violate}, which loses certainty
in the safe direction.

\paragraph{Replaying the pipeline itself.}
The measurements above concern the checker and need no model. The extraction
pipeline does call one, and a recorded run is replayed offline by
\texttt{python3 -m pytest test\_replay.py}: prompts are stored as SHA-256
hashes with their responses, so the pipeline can be re-executed without an API
key and without redistributing source documents. A tape that no longer matches
the code \emph{skips} rather than passes.
